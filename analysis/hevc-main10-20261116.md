# Renoir HEVC Main10 encode bring-up — 2026-11-16

Target: Ryzen 7 PRO 4750U, PCI `0x1636`, macOS 26.7.2 / `25G332`.
Cache, VA/GVA and kernel identities are pinned by `MediaPatchManifest.json`.

## Implemented behavior

The reviewed patch set enables public VideoToolbox Main10 hardware encoding on
the tested Renoir device, subject to normal media readiness and boot opt-outs.
The personality XML remains Main-only. The injector copies its nested HEVC
encode dictionaries, adds profile 2 at the existing maximum level 153, and
publishes the string capability `"2"` last. Unsupported devices/builds, a failed
backend and `-NRedNoVDA`, `-NRedNoHEVC`, or `-NRedNoHEVC10` cannot enable Main10.
Allocation/insertion failure cannot publish level 2 prematurely.

There are four additional required instruction windows:

| Function | Offset | Purpose |
| --- | --- | --- |
| `VAUveEncoder::EncodePicture` | `0x14a` | Supply the actual source texture to the format builder |
| `Vcn2Encoder::setInputAndOutputFormatParams` | `0x1f` | Detect two-byte P010 elements and set depth/packing together |
| `AvdVcn2HevcHeaderEncode::encodeSliceHeader` | `0x520` | Signal zero slice Cb delta |
| Same header writer | `0x530` | Signal zero slice Cr delta |

The extended manifest requires 18 sites across 11 pages. Full-page hashes mask
only declared windows; each window must contain its exact original or exact
replacement. Freshly faulted pages remain independently validated.

## Causes and experiments

1. AppleGVA reads `IOGVAHEVCEncode` as an encode capability level. The original
   `"1"` rejects Main10 profile selection with `-12900`; `"2"` accepts it.
   An attempted userspace registry write returned success but readback stayed
   `"1"`. A process-local interposer verified the capability branch separately.
2. The encoder context can retain its original NV12 fourcc for a P010 source.
   The original P010 branch also sets depth 1 but leaves packing 0. The fix
   supplies the actual source texture and emits depth 1 / P010 packing 1.
   **NV12 and P010 both use internal enum `0x13`.** The final fix distinguishes
   their bytes-per-element field at texture offset `0x84`: 1 versus 2.
   RGB paths retain their existing context selection and constants.
3. AppleGVA's Main10 slice header requests Cb 0 / Cr −3, but the native VCN2
   command contains Cb 0 / Cr 0. Constant Cb=Cr=256 input reconstructed Cb
   correctly and Cr around 330 instead of 256. Temporarily normalizing the
   slice Cr delta to 0 improved Cr PSNR from about 23 to about 62 dB.
   A separate attempted hardware-packet synchronization did serialize Cr −3
   in command `0x100003`, but output remained byte-identical to the incorrect
   stream. That ineffective command-function rewrite is **not shipped**.
   The final fix explicitly signals zero slice deltas, matching tested output.
   PPS data and luma/rate-control settings are left to the native driver.

The previous restart came from a different byte-pitch experiment: changing the
source element divisor from 2 to 1 doubled the programmed source pitch. The
first GPU fault was on the encoder queue, followed by resets and a WindowServer
watchdog panic. That experiment is excluded from this patch set.

The working P010 input uses CPU IOSurface pitch 3840 bytes at width 1920, a GPU
staging texture pitch of 4096 bytes, and source-command pitches 2048/1024 in
elements. These describe different surfaces/element sizes. They must not be
substituted for one another. Native Main10 reference allocation already accounts
for two-byte elements; the fix does not double the source command pitch.

## Validation

Runtime trials patched only the test processes, with exact-byte checks before
submission. The local factory was the original Apple-signed HEVC plugin, selected
on the actual Metal registry ID. The running kext during these trials was the
previous hardened revision 3. No trial patched the system bundle or EFI.

| Cases | Frames per case | Result |
| --- | --- | --- |
| Main10 at 1920×1080, 1918×1080, 3840×2160 | 3, then 30 | All six pass |
| HEVC Main 8-bit at the same dimensions, with final patches | 3, then 30 | All six pass |
| HEVC Main 8-bit without the new patches | 30 | All three streams byte-identical to their patched counterparts |
| Public-API H.264/HEVC encode/decode and AVC/HEVC/Main10 B-frame decode under revision 3 | 30 | All nine pass |

Both encode and decode require hardware and query actual hardware selection.
Every effective-pixel hardware decode hash matches independent PyAV/FFmpeg
software decoding, with no dropped/missing frames. Main10 source values vary the
low two bits as well as the high eight bits. Sampled source PSNR is measured
directly at ten-bit precision; the minimum across the 30-frame Main10 cases is
48.253 dB. No new GPU restart report, recovery count increment or VCN resource
failure was observed during the final matrix.

Host checks execute the actual format-builder instructions with mocked command
objects across P010/NV12/RGB and AVC/HEVC cases. They also execute the exact signed
chroma-offset loads, test capability ownership and allocation/insertion failures,
and exercise media policy, fresh-page lifecycle, changed-page rejection and
ten-bit reference generation. They submit no GPU work.

All raw trial programs, media, logs, debugger scripts and failed candidates are
kept outside the source checkout. The native kext build completed. The existing
xmake 3.1.2 archive helper tries to open an uncreated stdin list when given a
string input; packaging succeeds with an explicit table of bundle names.

## Post-boot acceptance still required

The process-local matrix validates the instruction replacements and output,
not the boot-installed personality/pager route. After installing/rebooting,
verify revision 4, Main10 advertisement, 11-page/18-site coverage, then run:

```sh
VDA_TEST_PYTHON=/path/to/python-with-pyav-and-numpy \
  tools/vda_hwtest.sh --require-main10
```

This must use public encoder selection without the temporary factory/interposer
or debugger. Until it passes, EFI installation is complete but boot integration
acceptance remains pending. No claim is made for HDR metadata, sustained 4K60,
sleep/wake, concurrent playback/recording or long-term stability.
